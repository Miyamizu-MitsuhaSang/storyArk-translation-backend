# 用户设置分域与可扩展设计

## 1. 目标与范围

本设计为账户界面偏好和项目业务配置建立清晰的设置边界，并确保后续新增字段、校验规则和设置区域时不需要重构现有数据模型。

本期涉及三个设置作用域：

1. `AppearanceSettings`：用户级外观设置，目前包括 `theme`，取值为 `light`、`dark`、`system`。
2. `UserPreferences`：用户级、跨设备同步的账户偏好，目前只包括界面语言 `locale`，例如 `zh-CN`、`en-US`。这里的语言只表示网站界面语言，不表示翻译任务的源语言或目标语言。
3. `ProjectSettings`：项目级业务配置，继续使用现有项目翻译设置实现，由项目管理员维护，不迁移到用户设置表。

本设计不引入一个混合所有设置的通用 JSON 表，也不把设置字段直接塞入 `auth_users` 或登录令牌响应。

## 2. 设计决策

### 2.1 采用独立作用域，而不是单一 settings 表

每个作用域拥有独立的数据模型、服务边界、API 响应分组和迁移。这样可以：

- 让账户偏好和项目配置拥有不同的权限模型；
- 在不影响用户设置的情况下扩展项目配置；
- 对字段使用强类型校验、索引和数据库约束；
- 避免 JSON 字段失去类型约束、查询能力和 OpenAPI 描述。

### 2.2 表的扩展策略

每个 settings 表预留稳定的主键、所属主体唯一约束、创建/更新时间和版本字段。新增设置时遵循以下规则：

- 新增稳定业务字段时，增加明确类型的列、Pydantic schema 字段、服务层映射和数据库迁移；
- 新增枚举值时，同时更新白名单校验、API 文档和前端显示映射；
- 新增一个独立设置区域时，创建新的表和命名空间，不复用不相关表的 JSON 字段；
- 不使用无约束的 `dict[str, Any]` 作为公开 API 的主要契约；
- 需要高频实验或暂未稳定的字段，可在应用层做 feature flag，但稳定后必须迁移为显式字段；
- 所有更新接口使用 PATCH 语义，未提交的字段保持原值，并保留并发控制字段 `revision`（若该表已有版本控制则沿用现有机制）。

### 2.3 默认值和创建时机

用户首次读取设置时，如果对应记录不存在，由服务层按默认值创建或返回等价默认对象；默认值必须集中定义，不从前端推断。推荐默认值为：

- `theme = "system"`；
- `locale = "zh-CN"`，后续可根据产品默认语言调整；
- 项目设置继续遵循当前项目模板和现有服务逻辑。

## 3. 数据模型

建议新增两个用户级表，项目设置沿用现有模型。

### 3.1 `auth_appearance_settings`

- `id`：UUID 主键；
- `user_id`：指向 `auth_users.id`，唯一且级联删除；
- `theme`：短字符串白名单，`light`、`dark`、`system`；
- `revision`：整数版本，默认 1；
- `created_at`、`updated_at`：继承统一时间字段。

### 3.2 `auth_user_preferences`

- `id`：UUID 主键；
- `user_id`：指向 `auth_users.id`，唯一且级联删除；
- `locale`：界面语言代码，长度受限并由服务层白名单校验；
- `revision`：整数版本，默认 1；
- `created_at`、`updated_at`：继承统一时间字段。

### 3.3 现有项目设置

现有 `ProjectSettings`/翻译设置模型继续以 `project_id` 为主体，并由项目成员权限控制。未来新增项目设置字段必须在该作用域内演进，不能复用 `auth_user_preferences`。

## 4. API 契约

统一挂载在 `/api/v1/auth` 下，并要求当前登录用户。

### 4.1 聚合读取

`GET /api/v1/auth/me/settings`

返回：

```json
{
  "appearance": {
    "theme": "system",
    "revision": 1,
    "updated_at": "2026-10-09T00:00:00Z"
  },
  "preferences": {
    "locale": "zh-CN",
    "revision": 1,
    "updated_at": "2026-10-09T00:00:00Z"
  }
}
```

### 4.2 部分更新

`PATCH /api/v1/auth/me/settings`

请求体允许包含 `appearance`、`preferences` 中任意一个或两个分组；分组内只更新出现的字段。非法主题、未支持的界面语言、错误 revision 返回结构化 4xx 错误。服务端根据当前用户身份隔离数据，客户端不能通过请求体指定 `user_id`。

项目设置继续使用现有 `/api/v1/projects/{project_id}/...` 路由和项目管理员权限。

## 5. 前后端职责

### 5.1 后端职责

- 在数据库中保存跨设备事实来源；
- 通过认证依赖隔离当前用户；
- 创建默认记录并执行白名单、长度和 revision 校验；
- 提供聚合读取与 PATCH 接口；
- 生成 OpenAPI description，并同步 `api-contract/docs/api.md` 和后端文档副本；
- 编写迁移、服务测试、路由测试和并发更新测试；
- 不负责渲染具体界面，不决定浏览器的系统主题检测。

### 5.2 前端职责

- 登录后读取 `/auth/me/settings`，将设置注入应用状态；
- `locale` 只控制网站界面文案加载，不修改翻译任务语言方向；
- `theme=system` 时监听系统主题，`light`/`dark` 时使用显式值；
- 修改设置后调用 PATCH，并在成功后更新本地状态；
- 本地缓存只作为启动阶段优化，后端响应是跨设备的事实来源；
- 对后端返回的未知未来字段保持向后兼容，忽略无法识别字段而不破坏现有页面。

## 6. 错误、权限与兼容性

- 未登录请求返回现有认证错误；
- 用户只能读取和修改自己的用户设置；
- 项目设置仍按项目成员/管理员权限校验；
- 不支持的枚举值返回可定位的字段错误；
- PATCH 空对象视为无变更并返回当前设置；
- 新增字段采用可选或带默认值的响应字段，避免破坏旧客户端；
- 删除字段需要先经历弃用周期，不直接删除数据库列或 API 字段。

## 7. 测试与验收

- 数据模型：唯一用户约束、级联删除、默认值和迁移可重复执行；
- 服务层：首次读取创建默认值、部分更新、非法枚举、revision 冲突和用户隔离；
- API：认证、GET/PATCH、错误响应、OpenAPI description；
- 前端：主题三态切换、界面语言切换、刷新和跨会话加载、未知字段兼容；
- 回归：现有项目翻译设置 API 不受用户设置新增影响。

## 8. 后续扩展示例

用户级可扩展字段可加入 `AppearanceSettings` 的 `density`、`reduce_motion`，或 `UserPreferences` 的 `timezone`、`date_format`。项目级可继续加入翻译工作流默认值、术语规则开关等。每项扩展都应在所属表中增加显式字段并配套迁移、schema、服务、文档和测试。
